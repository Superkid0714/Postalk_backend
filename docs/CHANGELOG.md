# 변경 묶음과 검토 순서

이 변경은 Lucel 작성자 정보로 다음 단위로 나눠 커밋합니다.

## 후속: Render API·워커 배포 준비

- Node 22 / Debian 기반 FFmpeg·한글 폰트·비특권 실행, API와 경량 HTTP 복구 워커 이미지 분리
- Singapore 리전 API 2GB·워커 512MB Blueprint, 내부 주소·인증키 참조 및 초기 워커 비활성화
- 프론트 CORS 환경 설정, Render 기본 URL 지원, health 응답에 소스 revision 추가
- 읽기 전용 배포 smoke 도구, CORS 및 실제 로컬 워커 요청 회귀 검사
- 서버·도메인이 없는 경우의 비용·배포·롤백·행사 종료 절차 문서화

## 후속: 실제 기존 Supabase 복구·SQL·Storage 적용 (2026-11-03 KST)

- 일시 중지된 기존 프로젝트 Resume, 기존 14개 테이블 행 수 보존 후 22개 앱 테이블과 미사용 레거시 5개 테이블 유지
- 영상 제약조건의 PostgreSQL `IN` → `ANY` 표현 차이로 인한 마이그레이션 실패 수정
- 원자적 기존 DB 업그레이드 묶음, 이전 검수 상태 기록, 오래 멈춘 작업 2개의 재호출 방지 및 원래 기술 상태 보존
- 실제 DB에서 RLS·서버 권한·호환 뷰·RPC·중복 요청·캡션·삭제 검증 통과, 임시 데이터 롤백
- 기존 비공개 uploads 유지, 50MiB 및 허용 MIME 설정, 합성 PNG 왕복·서명 다운로드·공개 접근 차단·테스트 파일 정리 통과
- Pro 결제·프론트 배포·외부 AI/Instagram 호출은 이번 DB·Storage 적용에 포함하지 않음

## 후속: Supabase Pro 전시 미디어 운영

- 사진 10MiB·영상 50MiB를 비공개 버킷과 통일, 정책 GET과 실제 바이트 기준 multipart 52MiB 상한
- 제작 상태 사전 확인으로 시작된 제작의 불필요한 검사/추가 저장 방지, 저장소 크기·혼잡·한도 오류 안내 분리
- 보관함에서 대표 이미지가 없을 때 원본 카드로 대체하던 다운로드 제거
- 프로젝트 DB 등록 용량을 읽는 점검 CLI, Supabase 기준 70GB 경고와 크기 미상/미참조 후보 표시
- 11월 18~21일 약 200건을 위한 Supabase Pro 운영 문서, AWS 이전 보류 및 프론트 제한 변경 안내
- 원본 자동 압축·TUS·파일 자동 삭제·실제 결제·운영 DB 변경은 실행하지 않음

## 후속: 별도 Supabase 테스트 환경 준비

- 빈 프로젝트 가드, 전체 설치 후 RLS·권한·RPC·제작 흐름 검증 및 임시 데이터 롤백 SQL
- 비공개 테스트 업로드 버킷 생성과 외부 서비스 설정을 상속하지 않는 staging 환경 예시
- 기존 가게·사용자·촬영·QR 6개 테이블의 RLS와 서버 전용 권한 보완
- 클라이언트 자동 권한 부여 상황을 재현하여 QR 테이블 접근 차단과 서버 접근을 PostgreSQL에서 검증
- 대시보드 연결 불가로 실제 테스트 프로젝트 생성·DB 적용은 미실행

## 후속: ERD 구조 구현·Supabase 유지

- 생성 세션·장면·불변 콘셉트 스냅샷·파일 카탈로그·생성 결과·게시 시도를 SQL과 기존 API에 연결
- 전시 테이블 세 개는 canonical 이름으로 변경하고 이전 이름의 updatable security-invoker 뷰 유지
- 기존 행을 트랜잭션으로 이관, 가게/작업 소유권 FK, 제출 입력 고정, 새 파일의 SHA-256과 작은 썸네일 카탈로그
- 게시 응답 유실·게시 후 DB 실패 시 재게시 차단, 확인 근거를 기록하는 서버 전용 복구 RPC
- Supabase DB/Storage 유지, 읽기 전용 파일 용량 집계 추가; AWS 배포·파일 이전·자동 삭제 없음
- 미구현 ERD 초안 대신 같은 구현 SQL에서 전체/제작 흐름 ERD를 함께 추출
- 최종 콘셉트·외부 AI 연결, 실제 Supabase 마이그레이션/통합 검증은 별도 적용 단계

## 1. 관리자 검수 제거·상인 게시·안정화

- 관리자 API 14개와 검수·승인·반려 전용 코드 제거
- 상인 가게 QR 권한 확인과 입력·첨부 파일 검증
- 콘텐츠 생성과 게시 분리: 상인이 게시 버튼을 누른 요청만 게시
- 생성·게시의 DB 실행 권한 선점과 내부 워커 복구
- 촬영 진행 상태를 덮어쓰지 않는 초안 병합
- 중복 활성 생성 작업 제한, 영상 유료 호출 전 작업 확보
- 실제 게시 기록만 게시 완료로 집계하고 사진·영상 보관함 조회 분리

## 2. AWS S3 저장소 호환 계층

- Supabase 기본 쓰기 유지, 환경 설정으로 S3 새 쓰기 활성화
- 기존 uploads 참조와 새 s3:bucket 참조의 동시 읽기
- 원본·생성 이미지·영상·썸네일·검수·미리보기·Instagram URL 연동
- 비공개 서명 URL, 덮어쓰기 방지 조건부 업로드, 객체 존재 확인
- 허용 버킷 제한과 과거 버킷 읽기를 통한 전환·롤백 지원

## 3. 보안 의존성 갱신

- Next.js 및 eslint-config-next 16.4.3 고정
- 기존 버전 범위의 전이 의존성 보안 패치
- 운영 의존성 취약점 0개 확인, 개발 도구 잔여 사항은 OPERATIONS.md에 기록

## 4. 이전 도구·SQL·AWS 인프라

- 기본 읽기 전용 목록, 명시적 --apply 복사·전환·롤백 도구
- 파일 크기·SHA-256·MIME 검증과 원본 보존
- 다섯 참조의 원자적 전환 RPC와 실제 PostgreSQL 엔진 테스트
- 비공개 S3·암호화·버전 관리·HTTPS·IAM·CORS CloudFormation 정의
- 실제 DB·AWS 배포·파일 이전은 실행하지 않음
