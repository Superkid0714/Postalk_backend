# 변경 기록

## 2026-11-21 Instagram 게시 지연 개선

- 실제 게시 시간·대기 기록과 Instagram 컨테이너 상태를 대조해, 짧은 요청 대기 이후 처리가 이어지지 않던 경로를 확인.
- 명시적 최신 /publish 요청만 자동 마무리하는 별도 워커 루프 추가. 오래된 요청·게시 결과 불확실·기시도 요청 제외.
- 카드뉴스 자식 컨테이너 생성 병렬도 2로 개선하고 원본 순서 보존.
- 동시 완료 처리의 잠금 충돌은 저장된 상태로 합류하며 중복 게시 방지 유지.
- 게시 준비·컨테이너 생성·게시 확인 구간별 시간 로그 추가.
- 전체 테스트 189개, 타입 검사·린트 통과. 과거 대기 5건은 변경하지 않음.


## 2026-11-19 카드뉴스 메뉴·사진 라벨 정합성

- 카드뉴스 AI의 제공 패치를 적용하고 부분 메뉴 입력, 메뉴 상세 입력, AI 미설정·인식 실패 경로를 보완했습니다.
- 생성 근거가 없는 문구 호출을 건너뛰고, 확인되지 않은 사진별 이름은 기본 라벨로 처리합니다.
- OpenAI 단계별 타임아웃 60초를 적용하며 SDK·대체 모델의 중첩 재시도를 막습니다.
- 백엔드의 다음 촬영 안내에 입력 메뉴명을 표시하고 공개 Swagger에 사진 역할 대응을 명시했습니다.
- AI 테스트 23개와 Chromium 4장 렌더, 백엔드 테스트 183개·타입·린트 통과.
- 새 AI 배포에서 미니멀·크리스마스 각 PNG 4장 생성·저장·홈·보관함 조회 통과. 최종 파일 제출 후 각각 약 88초·108초 소요.

## 2026-11-18 릴스 표지·문구 보완

- 완료된 릴스 생성 작업의 JPEG 썸네일을 Instagram `cover_url`로 전달합니다. 다른 작업의 표지는 사용하지 않습니다. 표지 없는 이전 결과는 `thumb_offset=1000`(밀리초)을 사용합니다.
- 릴스 AI는 첫 메뉴 클로즈업 중간 프레임을 우선 선택하고, 중앙 영역이 어두우면 영상 25%·50%·70% 지점과 밝기를 비교합니다. 전시용 릴스도 메뉴 장면 안쪽의 밝은 프레임을 선택합니다. 전체 영상이 어두운 경우 밝은 표지를 보장할 수는 없습니다.
- AI 입력에 부정·제한 조건이나 가상·테스트 안내가 있으면 해당 설명을 원문으로 캡션에 보존하고, 자막은 가게·메뉴 이름으로 구성합니다. 이 경우 방문·시식 유도 문구를 추가하지 않습니다.
- 보관함 릴스 응답의 `thumbnailUrl`은 JPEG 표지(없으면 null), `generatedAssetUrl`은 MP4 재생 URL입니다. 자산 정렬 순서에 따라 두 필드가 뒤바뀌던 오류를 수정했습니다.
- 프론트 요청 형식은 그대로입니다. 추가 표지 입력은 필요하지 않습니다. 이미 게시된 Instagram 게시물에는 소급 적용되지 않습니다.
- 릴스 작업 메타데이터의 재생 길이는 고정 13초 대신 실제 렌더 결과를 기록합니다.

## 2026-11-18

- 릴스 시작 요청에서 구조화된 `reelsMenus`가 있으면 `menuIntro`를 생략할 수 있도록 개선했습니다. 기존 문자열 요청은 계속 지원합니다.

- 게스트 최초 503의 직접 원인을 Supabase API Gateway의 `401/PGRST303`으로 확인하고 [원인 조사 기록](incidents/20261118-guest-session-503.md)을 추가했습니다.
- 서버용 secret 키의 중복 Bearer 전송을 제거하고 같은 오류를 기존 제한된 재시도에 포함했습니다. 권한 검증은 유지합니다.
- 게스트 세션 복구 정책과 503 응답·클라이언트 대응을 운영 Swagger와 연동 문서에 반영했습니다.
- 인증 수정 후 자동 테스트 174개와 운영 게스트 접속 16회, 두 콘셉트 릴스 생성·저장을 확인했습니다. 전체 UI·카드뉴스·Instagram 게시의 재검증을 의미하지 않습니다.
